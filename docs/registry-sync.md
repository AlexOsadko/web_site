# Синхронізація реєстру договорів між пристроями

Конструктор `osadko.online/dogovir/` веде реєстр договорів у браузері. Щоб той
самий реєстр був **на всіх ваших пристроях**, його можна синхронізувати через
ваш Cloudflare Worker. Дані клієнтів при цьому **шифруються у вашому браузері**
(наскрізне шифрування, E2E) — на сервер потрапляє лише зашифрований блок, який
без вашої **парольної фрази** не прочитає ніхто, зокрема Cloudflare.

> Це той самий воркер `osadko-relay`, що вже приймає заявки з форм. Ми лише
> додаємо йому маршрут `/registry` і сховище.

---

## Крок 1. Оновити код воркера

1. **dash.cloudflare.com** → **Workers & Pages** → відкрийте свій воркер
   (`osadko-relay`) → **Edit code**.
2. Замініть увесь вміст на актуальний файл
   [`telegram-worker.js`](./telegram-worker.js) з репозиторію (він тепер
   обробляє і заявки, і реєстр) → **Deploy**.

Заявки в Telegram працюватимуть, як і раніше — код зворотно сумісний.

## Крок 2. Створити сховище (KV) і прив'язати його

1. Ліворуч **Storage & Databases → KV → Create a namespace** → назва напр.
   `osadko-registry` → **Add**.
2. Поверніться у воркер → **Settings → Bindings → Add → KV namespace**:
   - **Variable name:** `REGISTRY_KV` (саме так, великими літерами);
   - **KV namespace:** оберіть щойно створений `osadko-registry`.
   - **Save**.

## Крок 3. Додати секретний токен

1. Воркер → **Settings → Variables and Secrets → Add**:
   - **Name:** `REGISTRY_TOKEN`, **Type:** Secret,
   - **Value:** будь-який довгий пароль (напр. 24+ випадкових символів).
     Це «ключ від дверей» — щоб чужі не могли смикати ваш реєстр.
2. Переконайтесь, що є `ALLOWED_ORIGIN` = `https://osadko.online` (Text).
3. **Deploy** ще раз.

## Крок 4. Увімкнути синхронізацію в застосунку

На кожному пристрої, де працюєте:

1. Відкрийте `osadko.online/dogovir/` → розділ **«Реєстр договорів»** →
   розгорніть **«☁ Синхронізація між пристроями»**.
2. Заповніть три поля:
   - **Адреса синхронізації** — вже підставлено
     `https://osadko-relay.espir3.workers.dev/registry` (якщо воркер інший —
     виправте, головне `…/registry` у кінці);
   - **Токен доступу** — той самий `REGISTRY_TOKEN` із кроку 3;
   - **Парольна фраза** — ваш секрет для шифрування (**однаковий на всіх
     пристроях**; на сервер не надсилається).
3. **«Синхронізувати зараз»**. Статус має стати **«Синхронізовано ✓»**.
4. Повторіть на інших пристроях із **тими самими** токеном і фразою.

Далі все автоматично: кожен новий договір оновлює хмарну копію; при відкритті
на іншому пристрої реєстр підтягується сам — разом зі знімками для повторного
формування.

---

## Безпека і застереження

- **Парольну фразу не можна відновити.** Якщо її забути — зашифровані дані
  втрачені назавжди (у цьому й сенс E2E: навіть Cloudflare не має ключа).
  Запишіть її в менеджері паролів.
- **Тримайте .xlsx-бекап** (кнопка «Експортувати реєстр») як страховку.
- Токен і фраза зберігаються **лише у браузері** того пристрою (localStorage) —
  на спільних/чужих комп'ютерах не вводьте.
- Якщо ввести **невірну фразу**, застосунок покаже помилку й **не затре**
  хмарну копію — ваші дані в безпеці.
- Синхронізація об'єднує записи за номером договору. Якщо працюєте одночасно
  на двох пристроях — спершу відкрийте/синхронізуйте, потім додавайте нові.

## Якщо щось не так

| Статус у панелі | Причина / дія |
|---|---|
| «Помилка звʼязку: сервер 403» | Невірний токен, або не задано `ALLOWED_ORIGIN` / зайшли не з osadko.online |
| «kv_not_configured» (сервер 500) | Не прив'язано `REGISTRY_KV` — крок 2 |
| «Невірна парольна фраза…» | Фраза відрізняється від тієї, якою шифрували на іншому пристрої |
| «Не налаштовано» | Заповніть усі три поля й натисніть «Синхронізувати зараз» |
