# Стандарт статей сайту (обов'язкові вимоги)

Єдиний стандарт для **всіх нових і оновлюваних статей** каталогу
(`content/articles/*.json` → рендер `tools/build.py`). Стаття вважається
готовою до публікації, лише якщо відповідає **всім** пунктам нижче.

## 1. Формат файлу

JSON у `content/articles/<slug>.json`:

```json
{
  "slug": "...",            // латиниця, унікальний, без дублів
  "cat": "...",             // одна з категорій (див. §7)
  "title": "...",           // SEO-заголовок (тег <title>)
  "h1": "...",              // заголовок сторінки
  "desc": "...",            // meta description, 1–2 речення
  "order": 000,             // наскрізний, продовжувати з максимального
  "date_published": "РРРР-ММ-ДД",
  "date_modified": "РРРР-ММ-ДД",
  "blocks": [ ... ],        // типи: p, h2, ul
  "faq": [ {"q":"...","a":"..."} ]
}
```

Типи блоків: `p` (абзац), `h2` (розділ), `ul` (`items[]` — маркований список).

## 2. Обсяг (жорсткі межі)

| Параметр | Мінімум | Ціль | Максимум |
|---|---|---|---|
| Розділів H2 | 8 | **11** (10 змістовних + «З чого почати») | 11 |
| Слів (щільних, без «води») | **1000** | 1000–2000 | 2000 |
| FAQ | 6 | **8** | 8 |

> **Правило, перевірене на практиці:** надійний спосіб з першого проходу
> вийти на ≥1000 слів — це **рівно 11 розділів H2 з повнофразовими
> списками**. Менша кількість секцій або короткі пункти дають лише
> ~750–850 слів і потребують доведення в кілька ітерацій. Не економте на
> секціях і на довжині пунктів.

Слова рахуються за формулою (сума слів у `text` та `items` усіх блоків):

```python
w = sum(len(str(b.get("text","")).split())
        + sum(len(x.split()) for x in b.get("items",[]))
        for b in blocks)
h2 = sum(1 for b in blocks if b["type"] == "h2")
assert 8 <= h2 <= 11 and w >= 1000
```

## 3. Структура (надійна формула обсягу)

**Формула «11 H2 з повнофразовими списками»** — стандарт де-факто:

- **Вступ** — 2 абзаци `p` (≈90–110 слів): перший — суть теми, другий — анонс
  того, що розкрито в статті.
- **10 змістовних розділів H2**, кожен = лід-абзац `p` (**2 речення, ≈40 слів**)
  + список `ul` на **6–7 пунктів**. **Кожен пункт — повнофразовий**: з
  виділенням `<b>…</b>` на початку і **завершеною думкою у ≥10 слів**
  (наприклад: «<b>строк оскарження</b> — протягом десяти днів з дня винесення
  постанови, інакше вона набирає чинності»). Пункти на 3–4 слова
  («<b>строк</b> — 10 днів») **не дають потрібного обсягу** і заборонені.
- **11-й розділ «З чого почати»** — абзац `p` на **≈110–140 слів**.

Ця формула стабільно дає ≥1000 слів:
`≈100 (вступ) + 10×(≈40 лід + ≈75 список) + ≈130 (фінал) ≈ 1400`.

Що **не** працює (перевірено — дає лише ~750–850 слів, потребує доведення):
- менше ніж 10 змістовних розділів;
- односкладові ліди (1 речення);
- короткі списки (5 пунктів) чи пункти по 3–5 слів;
- «добивання» обсягу лише подовженням фіналу — фінал має лишатися ≈130 слів,
  обсяг набирається **секціями й повнофразовими пунктами**, а не «водою».

## 4. Обов'язкові розділи

У кожній статті мають бути (назви адаптуються під тему):

1. **Право / підстава / що це** — правова основа з нормою.
2. **«Необхідні документи»** або **«Порядок дій»** (кроки).
3. **Строки** (процесуальні, давності, виплат тощо) — де застосовно.
4. **Розмір / суми** — де застосовно (виплати, штрафи, збори).
5. **Оскарження / спори / відмова** — де застосовно.
6. **«Типові помилки»**.
7. **«З чого почати»** — практичний фінал.

Плюс тематичні розділи (особливі випадки, окремі категорії, практика,
роль адвоката тощо), **щоб разом вийшло 10 змістовних розділів + «З чого
почати» = 11 H2**.

## 5. Юридична якість

- **Реальні норми**: конкретні статті ЦК/СК/КЗпП/КК/КУпАП/ЦПК/ГПК/КАСУ/ЗК/ПКУ
  та профільних законів; реальні строки, суми, органи, процедури.
- **Без «води»**: жодних загальних фраз-наповнювачів. Кожен пункт несе
  конкретну інформацію.
- Українською мовою, юридично коректно, зрозуміло для клієнта.

## 6. FAQ

8 питань-відповідей (мінімум 6). Питання — реальні запити користувачів;
відповіді — 2–4 речення з конкретикою й нормами. Живить FAQPage-розмітку.

## 7. Категорії (`cat`)

`criminal`, `military`, `civil`, `labor`, `family`, `business`, `admin`,
`process`, `social`, `auto`, `realty`.

## 8. Унікальність

Перед створенням перевірити, що `slug` **і тема** не дублюють наявні статті
(`ls content/articles` + пошук за ключовими словами). `order` — продовжувати
з максимального.

## 9. Чек-лист перед публікацією

1. `H2 == 11` (ціль) і `слів >= 1000` (перевірити скриптом із §2); мінімально
   допустимо `8 <= H2 <= 11`, але за `H2 < 11` перевірте обсяг особливо ретельно.
2. Присутні обов'язкові розділи (§4), 8 FAQ; кожен пункт списків — повнофразовий.
3. `ast.parse` скрипта-генератора; валідний JSON усіх файлів.
4. `python3 tools/build.py` — без помилок.
5. Деплой у гілку `claude/osadko-lawyer-website-8z6ifu` + fast-forward у `main`.

> Примітка: у README згадано «8–11 розділів, ~1000–2000 слів, 6–8 FAQ» —
> цей файл є деталізованим і чинним стандартом. За розбіжностей діє цей файл.
