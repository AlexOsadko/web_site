# Стандарт статей сайту (обов'язкові вимоги)

Єдиний стандарт для **всіх нових і оновлюваних статей** каталогу
(`content/articles/*.json` → рендер `tools/build.py`). Стаття вважається
готовою до публікації, лише якщо відповідає **всім** пунктам нижче.

## 1. Формат файлу

JSON у `content/articles/<slug>.json`:

```json
{
  "slug": "...",            // латиниця, унікальний, без дублів
  "cat": "...",             // одна з категорій (див. §7)
  "title": "...",           // SEO-заголовок (тег <title>)
  "h1": "...",              // заголовок сторінки
  "desc": "...",            // meta description, 1–2 речення
  "order": 000,             // наскрізний, продовжувати з максимального
  "date_published": "РРРР-ММ-ДД",
  "date_modified": "РРРР-ММ-ДД",
  "blocks": [ ... ],        // типи: p, h2, ul
  "faq": [ {"q":"...","a":"..."} ]
}
```

Типи блоків: `p` (абзац), `h2` (розділ), `ul` (`items[]` — маркований список).

## 2. Обсяг і щільність

> ⚠️ **Головне правило: щільність важливіша за кількість слів.** Не «добивайте»
> статтю до числа наповнювачем — це **прямо погіршує** матеріал. Краще щільні
> 650 слів із реальними нормами, ніж 1000 слів із водою. Це перевірено на
> практиці: коли статті штучно доводили до 1000 слів, щільність корисної
> інформації падала майже вдвічі, а половина текстів отримала однакові
> шаблонні речення.

| Параметр | Мінімум | Орієнтир | Стеля |
|---|---|---|---|
| Розділів H2 | 6 | **8–11** | 11 |
| Слів (щільних, без «води») | 600 | **700–1500** | ~2000 |
| FAQ | 6 | **8** | 8 |
| Щільність норм (згадок норм на 100 слів) | — | **≥0,5** | — |

- **Обсяг — орієнтир, а не жорстка вимога.** Стаття не «непрохідна» через 850
  слів, якщо вони змістовні. Немає сенсу нарощувати обсяг заради числа.
- **H2:** 8–11 — норма; менше 6 — замало структури.
- **Заборонено:** дублювати ті самі речення-поради між статтями. Кожне речення
  має бути унікальним і про конкретну тему (перевірка: жодне речення не
  повторюється дослівно у ≥3 статтях).

```python
w = sum(len(str(b.get("text","")).split())
        + sum(len(x.split()) for x in b.get("items",[])) for b in blocks)
h2 = sum(1 for b in blocks if b["type"] == "h2")
assert 6 <= h2 <= 11 and w >= 600         # мінімальні межі
# і головне — щільність: реальні норми в кожному розділі, без шаблонних дублів
```

## 3. Структура

- **Вступ** — 1–2 абзаци `p`: суть теми + анонс.
- **Змістовні розділи H2** (орієнтир 8–11), кожен = лід-абзац `p` + список `ul`.
  **Кожен пункт — повнофразовий і конкретний**: `<b>…</b>` на початку і
  завершена думка з реальною нормою/строком/сумою (наприклад: «<b>строк
  оскарження</b> — протягом десяти днів з дня винесення постанови»). Пункти
  на 3–4 слова («<b>строк</b> — 10 днів») малоінформативні.
- **Фінальний розділ «З чого почати»** — абзац `p` (≈90–130 слів) з
  **практичними кроками саме для цієї теми**, без загальних фраз.

**Обсяг набирається реальним змістом** — додатковими розділами з нормами,
процедурами, строками, сумами, — **а не подовженням фіналу й не повторюваними
порадами**. Якщо тема вичерпана на 8 розділах — так і лишіть; не розбавляйте.

## 4. Обов'язкові розділи

У кожній статті мають бути (назви адаптуються під тему):

1. **Право / підстава / що це** — правова основа з нормою.
2. **«Необхідні документи»** або **«Порядок дій»** (кроки).
3. **Строки** (процесуальні, давності, виплат тощо) — де застосовно.
4. **Розмір / суми** — де застосовно (виплати, штрафи, збори).
5. **Оскарження / спори / відмова** — де застосовно.
6. **«Типові помилки»**.
7. **«З чого почати»** — практичний фінал.

Плюс тематичні розділи там, де тема цього потребує (особливі випадки, окремі
категорії, практика). Додавайте їх, **лише якщо є реальний зміст**, а не для
збільшення кількості розділів.

## 5. Юридична якість

- **Реальні норми**: конкретні статті ЦК/СК/КЗпП/КК/КУпАП/ЦПК/ГПК/КАСУ/ЗК/ПКУ
  та профільних законів; реальні строки, суми, органи, процедури.
- **Без «води»**: жодних загальних фраз-наповнювачів. Кожен пункт несе
  конкретну інформацію.
- Українською мовою, юридично коректно, зрозуміло для клієнта.

## 6. FAQ

8 питань-відповідей (мінімум 6). Питання — реальні запити користувачів;
відповіді — 2–4 речення з конкретикою й нормами. Живить FAQPage-розмітку.

## 7. Категорії (`cat`)

`criminal`, `military`, `civil`, `labor`, `family`, `business`, `admin`,
`process`, `social`, `auto`, `realty`.

## 8. Унікальність

Перед створенням перевірити, що `slug` **і тема** не дублюють наявні статті
(`ls content/articles` + пошук за ключовими словами). `order` — продовжувати
з максимального.

## 9. Чек-лист перед публікацією

1. `6 <= H2 <= 11` і `слів >= 600` (орієнтир 700–1500); **щільність важливіша
   за довжину** — не нарощуйте обсяг наповнювачем.
2. Присутні обов'язкові розділи (§4), 6–8 FAQ; кожен пункт списків —
   повнофразовий; **жодне речення не повторюється дослівно в інших статтях**.
3. `ast.parse` скрипта-генератора; валідний JSON усіх файлів.
4. `python3 tools/build.py` — без помилок.
5. Деплой у гілку `claude/osadko-lawyer-website-8z6ifu` + fast-forward у `main`.

> Примітка: у README згадано «8–11 розділів, ~1000–2000 слів, 6–8 FAQ» —
> цей файл є деталізованим і чинним стандартом. За розбіжностей діє цей файл.
