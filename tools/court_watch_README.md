# Бот відстеження судових справ

Стежить за офіційними сторінками судів **«Список справ, призначених до
розгляду»** (court.gov.ua) і надсилає адвокату **приватне** сповіщення в
Telegram, коли призначено засідання у справі, де фігурує вказане ПІБ.
У канал `@pro100_law` нічого не потрапляє — це конфіденційно (адвокатська
таємниця).

Що приходить у сповіщенні: **номер справи, суддя (склад суду), дата й час
засідання, сторони, суть, форма судочинства, зал/кабінет, адреса**.

## Як це працює

Дані всіх судів віддає **один домен** `court.gov.ua` за кодом суду. Для кожного
суду бот повторює звичайний сценарій браузера:
1. `GET` сторінки `court.gov.ua/sud<код>/gromadyanam/csz` — отримати cookie сесії;
2. `POST court.gov.ua/new.php` з тим самим cookie — JSON з усіма засіданнями суду.

Перелік судів **вбудований** у бота (`tools/court_registry.json`) — вам не треба
вказувати суди. Бот залишає лише ті засідання, де у полі «сторони» зустрічається
одне з ваших ПІБ, і надсилає їх у приватний чат. Уже надіслані засідання
запам'ятовуються (`.court-bot/state.json`), тож повторів не буде; нова дата або
новий суддя у тій самій справі = нове сповіщення. Між судами бот робить паузу,
щоб не навантажувати сервер.

## Налаштування (одноразово)

### 1. Секрет `COURT_WATCH` — лише ПІБ клієнтів

**Settings → Secrets and variables → Actions → New repository secret**,
ім'я `COURT_WATCH`, значення — JSON. У найпростішому вигляді:

```json
{
  "names": ["Мещеряков Денис Валерійович", "Іваненко Іван Іванович"]
}
```

- **`names`** — список ПІБ для відстеження. **Головне — вказувати ПІБ
  КЛІЄНТА**, а не адвоката: дані про захисника суд фіксує не завжди, і адвокат
  може вступити у справу не з самого початку. ПІБ клієнта натомість присутнє у
  справі від реєстрації. Пишіть повне ПІБ (Прізвище Ім'я По-батькові) — так збіг
  найточніший; збіг також спрацює, якщо у списку суду порядок слів інший.
- **Суди задавати не потрібно** — бот сканує вбудований перелік
  (`tools/court_registry.json`). Наразі це **всі 10 районних судів міста Києва**;
  перелік «що зростає» — нові суди додаються рядком `{"code":"NNNN","name":"…"}`.
  Скажіть мені, який суд/місто додати — і я внесу (код суду перевіряється через
  Actions → «Пробник суду»).

**Додати власні суди** (замість або на додачу до вбудованих) можна прямо в
секреті — полем `courts` з кодом суду:

```json
{
  "names": ["Прізвище Ім'я По-батькові"],
  "courts": [
    {"code": "2604", "name": "Дніпровський районний суд м. Києва"},
    {"code": "2610", "name": "Шевченківський районний суд м. Києва"}
  ]
}
```

Якщо вказати `courts`, бот скануватиме саме їх (вбудований перелік не додається).
Щоб і свій список, і вбудований — залиште `courts` порожнім і назвіть мені
потрібні додаткові суди для реєстру.

### 1b. Керування списком прямо з Telegram (меню бота)

Замість редагування секрету можна вести список клієнтів **у чаті з ботом** —
надішліть боту **`/menu`** (або `/start`). Меню **закріплюється клавіатурою внизу,
біля поля вводу** — кнопки завжди під рукою. Пункти:

- **➕ Додати клієнта** — бот попросить ПІБ, ви надсилаєте його одним повідомленням;
- **📋 Список / кількість** — показує всі прізвища та їх кількість; біля кожного —
  кнопки **✏️** (змінити) і **🗑** (видалити).
- **👥 Справи клієнтів** — перегляд усіх майбутніх засідань ваших клієнтів
  (за списком ПІБ) з деталями: номер справи, дата/час, суд, зал, суддя, форма,
  суть, сторони, адреса. Біля кожної позначено, за яким клієнтом знайдено.
- **⚖️ Справи адвоката** — те саме, але для справ, де фігурує сам адвокат
  (за замовч. «Осадько Олександр Олексійович»); змінити ПІБ можна секретом
  `COURT_ADVOCATE`.
- **🔄 Терміновий прогін зараз** — не чекати планового часу, а запустити перевірку
  негайно (клієнти + адвокат; результат за ~1 хв). Потребує одноразового
  налаштування токена (нижче).

Обидва списки («клієнтів» і «адвоката») оновлюються під час кожного прогону —
планового (тричі на день) або термінового (кнопка 🔄).

### 1c. Терміновий прогін (кнопка 🔄) — токен GitHub

Щоб кнопка «Терміновий прогін» могла запускати перевірку на вимогу, воркеру
потрібен токен GitHub із правом запускати Actions:

1. GitHub → **Settings → Developer settings → Fine-grained tokens → Generate new token**.
2. **Repository access → Only select repositories →** `AlexOsadko/web_site`.
3. **Permissions → Repository → Actions → Read and write**.
4. Згенеруйте, скопіюйте токен.
5. Cloudflare → ваш Worker → **Settings → Variables and Secrets** → додайте секрет
   **`GH_TOKEN`** = цей токен → **Deploy**.

Без `GH_TOKEN` кнопка ввічливо повідомить, що терміновий прогін не налаштовано, —
а планові прогони тричі на день працюють у будь-якому разі.

Список зберігається **приватно** у сховищі Cloudflare Worker (KV), **не** у
відкритому репозиторії. Бот відстеження бере ПІБ і з меню, і з секрету
`COURT_WATCH` (об'єднує). Тобто секрет можна лишити порожнім і вести все з меню.

> Щоб меню запрацювало, оновіть код воркера (`worker/worker.js`) у Cloudflare —
> як робили для кнопок каналу (Edit code → вставити вміст → Deploy). Секрети
> воркера ті самі. Нічого більше додавати не треба.

### 2. Токен і чат

Бот використовує вже наявні секрети:
- `TELEGRAM_BOT_TOKEN` — той самий бот, що й для новин;
- `TELEGRAM_REVIEW_CHAT` — ваш Telegram id (куди приходять чернетки). Саме сюди
  прийдуть і сповіщення про справи.

Хочете інший чат для справ — додайте секрет `COURT_ALERT_CHAT` з потрібним id.

### 3. Перевірка

**Actions → «Відстеження судових справ» → Run workflow**, увімкніть
**dry_run** → у логах з'явиться кількість збігів по кожному суду (без
персональних даних). Якщо збіги є — вимкніть dry_run і запустіть ще раз:
сповіщення прийдуть у приватний чат.

## Розклад

Автоматично — тричі на день (10:00, 14:00, 18:00 за Києвом). Змінити можна у
`.github/workflows/court-watch.yml` (рядок `cron`).

## Обмеження

- Основне джерело — **призначені до розгляду** засідання конкретного суду. Це
  надійно покриває «дату призначення справи до розгляду», суддю та номер справи.
- Статус **«Призначено склад суду»** (автоматичний розподіл) можна вмикати
  окремо, додавши у запис суду `auto_url` (сторінка `…/gromadyanam/list_auto_cases/`).
  Це **експериментально**: суди віддають ці дані лише інтерактивному браузеру і на
  прямий запит повертають «error». У такому разі бот **тихо пропускає** цей крок —
  відстеження засідань від цього не страждає.
- Дані оновлюються судами вручну, тож момент появи засідання залежить від суду.
