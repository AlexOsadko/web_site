# Бот відстеження судових справ

Стежить за офіційними сторінками судів **«Список справ, призначених до
розгляду»** (court.gov.ua) і надсилає адвокату **приватне** сповіщення в
Telegram, коли призначено засідання у справі, де фігурує вказане ПІБ.
У канал `@pro100_law` нічого не потрапляє — це конфіденційно (адвокатська
таємниця).

Що приходить у сповіщенні: **номер справи, суддя (склад суду), дата й час
засідання, сторони, суть, форма судочинства, зал/кабінет, адреса**.

## Як це працює

Для кожного суду бот повторює звичайний сценарій браузера:
1. `GET` сторінки `…/sudNNNN/gromadyanam/csz` — отримати cookie сесії;
2. `POST /new.php` з тим самим cookie — повертає JSON з усіма засіданнями суду.

Далі бот залишає лише ті засідання, де у полі «сторони» зустрічається одне з
ваших ПІБ, і надсилає їх у приватний чат. Уже надіслані засідання
запам'ятовуються (`.court-bot/state.json`), тож повторів не буде; нова дата або
новий суддя у тій самій справі = нове сповіщення.

## Налаштування (одноразово)

### 1. Секрет `COURT_WATCH`

**Settings → Secrets and variables → Actions → New repository secret**,
ім'я `COURT_WATCH`, значення — JSON:

```json
{
  "names": ["Мещеряков Денис Валерійович", "Іваненко Іван Іванович"],
  "courts": [
    {"name": "Дніпровський районний суд м. Києва",
     "url": "https://dn.ki.court.gov.ua/sud2604/gromadyanam/csz"},
    {"name": "Шевченківський районний суд м. Києва",
     "url": "https://sh.ki.court.gov.ua/sud2610/gromadyanam/csz"}
  ]
}
```

- **`names`** — список ПІБ для відстеження. **Головне — вказувати ПІБ
  КЛІЄНТА**, а не адвоката: дані про захисника суд фіксує не завжди, і адвокат
  може вступити у справу не з самого початку. ПІБ клієнта натомість присутнє у
  справі від реєстрації. Пишіть повне ПІБ (Прізвище Ім'я По-батькові) — так збіг
  найточніший; збіг також спрацює, якщо у списку суду порядок слів інший.
  За бажанням можна додати й власне ПІБ адвоката.
- **`courts`** — суди, які перевіряти. `url` — сторінка «Список справ,
  призначених до розгляду» відповідного суду. Знайти її просто: сайт суду →
  розділ **«Громадянам» → «Список справ, призначених до розгляду»**. Приклади
  адрес районних судів Києва:
  - Голосіївський — `https://gl.ki.court.gov.ua/sud2601/gromadyanam/csz`
  - Дніпровський — `https://dn.ki.court.gov.ua/sud2604/gromadyanam/csz`
  - Подільський — `https://pd.ki.court.gov.ua/sud2607/gromadyanam/csz`
  - Шевченківський — `https://sh.ki.court.gov.ua/sud2610/gromadyanam/csz`
- **`auto_url`** *(необов'язково, експериментально)* — у записі суду можна
  додати сторінку автопризначень, щоб ловити статус **«Призначено склад суду»**
  ще до призначення засідання, напр.:
  `{"name":"…","url":"…/gromadyanam/csz","auto_url":"https://dn.ki.court.gov.ua/sud2604/gromadyanam/list_auto_cases/"}`.
  Див. розділ «Обмеження» нижче — багато судів наразі не віддають ці дані
  автоматично; якщо суд повертає помилку, бот просто пропускає цей крок і
  відстеження засідань працює як звичайно.

### 2. Токен і чат

Бот використовує вже наявні секрети:
- `TELEGRAM_BOT_TOKEN` — той самий бот, що й для новин;
- `TELEGRAM_REVIEW_CHAT` — ваш Telegram id (куди приходять чернетки). Саме сюди
  прийдуть і сповіщення про справи.

Хочете інший чат для справ — додайте секрет `COURT_ALERT_CHAT` з потрібним id.

### 3. Перевірка

**Actions → «Відстеження судових справ» → Run workflow**, увімкніть
**dry_run** → у логах з'явиться кількість збігів по кожному суду (без
персональних даних). Якщо збіги є — вимкніть dry_run і запустіть ще раз:
сповіщення прийдуть у приватний чат.

## Розклад

Автоматично — тричі на день (10:00, 14:00, 18:00 за Києвом). Змінити можна у
`.github/workflows/court-watch.yml` (рядок `cron`).

## Обмеження

- Основне джерело — **призначені до розгляду** засідання конкретного суду. Це
  надійно покриває «дату призначення справи до розгляду», суддю та номер справи.
- Статус **«Призначено склад суду»** (автоматичний розподіл) бере окрема
  сторінка суду через параметр `auto_url`. Це **експериментально**: багато судів
  віддають ці дані лише інтерактивному браузеру і на прямий запит повертають
  «error». У такому разі бот **тихо пропускає** цей крок — відстеження засідань
  від цього не страждає. Там, де суд віддає дані, статус приходитиме автоматично.
- Дані оновлюються судами вручну, тож момент появи засідання залежить від суду.
